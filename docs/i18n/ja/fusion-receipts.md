# フュージョンレシート — 「レシート付きの選択的フュージョン」

Chimeraの推論コアはモデルの**パネル**をブレンドします(パネル → ジャッジ → シンセサイザー)。フュージョンは品質を買いますが、より多くのトークンを消費します。だから正直な問いは「フュージョンは良いか?」ではなく、「**ここでそれは見合ったのか?**」です。レシートは主張ではなく数字でそれに答えます。

すべてのフュージョン実行は**レシート**として価格化できます: 各アドバイザー(パネルメンバー)、ジャッジ、シンセサイザーのコスト — それぞれ*固有*のモデルの料金で — に加え、選択的モードがパネルを短絡させたかどうか。レシートを永続化すれば、公開可能な**コスト×品質カーブ**が得られます。

## 試してみる

```bash
# 1回の実行の、アドバイザーごとの詳細コストを表示:
chimera fuse "Explain CAP theorem simply" --show-cost

# 各実行のレシートをJSONLに追記し、カーブを要約する:
chimera fuse "..." --receipt runs.jsonl
chimera fuse "..." --receipt runs.jsonl --selective
chimera fusion-receipts runs.jsonl
```

`fusion-receipts` は**フュージョン率**(フルパネルが実際に実行された頻度 vs. 選択的な短絡)、既知の価格を持つ実行の平均/合計コスト、そして — レシートが合格/不合格の品質シグナルを持つ場合 — 合格率と**合格した回答1件あたりのドル**を報告します。

## 正直さのルール(構造による)

- **トークンは計測され、ドルは推定される。** トークン数はプロバイダーから来ますが、ドルの数値は概算の**公開リスト価格**で計算されるため、レシートは請求書ではなく推定器です。
- **未知のモデル → 未知のコスト、決してゼロではない。** どの段階でも価格未登録のモデルが実行された場合、レシートの合計は `None`(`unknown`)になります。そのため、価格の欠落が「無料」を装うことはできません。価格はコード内で上書き可能です(`chimera.fusion.set_price`)。
- **アドバイザーごとの帰属。** パネルのコストは*モデルごと*に内訳されるため(`receipt.advisor_costs`)、どのアドバイザーがその存在価値を発揮したかが分かります — スローガンではなく、選択的フュージョンを支える実体です。

## これが存在する理由

この分野はルーティング/カスケード(賭け金が正当化する場合にのみ多く使う)へと動き、常時オンのフュージョンから離れていきました。レシートはChimeraが**選択的にフュージョンし、それが見合ったことを証明する**ことを可能にするものです — コスト×品質カーブが証拠であり、フュージョンが役立た*なかった*実行も含めて公開されます。
